# Ограничения

Те же, что у ядра [`ds`](https://github.com/A1eksMa/ds).

| Ограничение | Почему |
|---|---|
| Только стандартная библиотека Python `>= 3.9` | Целевая среда запрещает установку сторонних пакетов. `pytest` — только для разработки. |
| Офлайн, без сетевых портов | Приложение ничего не слушает и не инициирует соединений. |
| Linux | Целевое окружение. |
| Функциональный стиль | `frozen` dataclass, чистые функции в `domain/`, эффекты изолированы за портами. Проще тестировать и рассуждать. |

## Планировщик — снаружи

`ds-loader run` (без `--once`) держит собственный цикл с `time.sleep`. Но в проде надёжнее
`ds-loader run --once` под `cron` / `systemd`-таймером: всё состояние — в журнале
(`ledger_path`), нет долгоживущего процесса, ОС отвечает за расписание и рестарт.
`--once` — надмножество: цикл = повторный вызов `run_once`.

## Совместимость с ядром

`ds-loader` завязан на CLI-контракт `ds`: форму `ds --db <p> load <dir> <file> --dt <ts>`,
код возврата (`0` — успех) и stdout (`loaded N transaction(s)`). Изменения этого контракта в
`ds` — повод обновить `ds-loader` (`src/domain/commands.py`, `docs/reference/`).
