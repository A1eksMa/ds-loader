# Обзор

## Зачем

`ds` — система записи: принимает выгрузки (`ds load`), хранит журнал, отдаёт состояние
(`ds get`). Но кто-то должен **гонять этот процесс**: следить за поступающими файлами,
вызывать `ds` в правильном порядке, разбирать сбои, а в будущем — пересобирать данные для
веб-морды и управлять жизненным циклом. Это и есть `ds-loader`.

`ds-loader` не хранит данные и не рисует UI. Он — тонкий оркестратор поверх CLI ядра.

## Роль в связке

```
┌───────────┐   файлы    ┌────────────┐  ds load / ds get   ┌──────┐
│ источники │ ─────────▶ │ ds-loader  │ ──────────────────▶ │  ds  │
└───────────┘  <src>_…   │ (оркестр.) │                     └──┬───┘
                         └─────┬──────┘                        │
                               │ data/*.js + manifest.js       │ состояние
                               ▼  (будущая стадия)             ▼
                         ┌────────────┐                   ┌──────────┐
                         │  ds-webui  │ ◀──── file:// ────│ снапшот  │
                         └────────────┘                   └──────────┘
```

## Модель стадий

Раннер (`src/app/runner.py`) за один тик прогоняет список **стадий** по порядку. Стадия —
функция `(Context) -> StageReport`. Какие стадии включены — задаёт `config.stages`.

Сейчас реализована одна: **`ingest`** (`src/app/ingest.py`). Будущие (`publish`, `lifecycle`,
`build` — см. [`../roadmap/README.md`](../roadmap/README.md)) добавляются в реестр
`STAGES` и в `_KNOWN_STAGES`, не меняя раннер.

Это ключевое архитектурное решение: «только приём сейчас, но с прицелом на полный
оркестратор» = один список стадий, растущий со временем.

## Чистая архитектура

| Слой | Пакет | Ответственность |
|---|---|---|
| domain | `src/domain/` | чистые типы и функции: разбор имени, метка → unix, порядок очереди, построение argv, ключ журнала. Без I/O. |
| ports | `src/ports/` | интерфейсы внешнего мира: `Clock`, `FileSystem`, `DsCli`, `Ledger` (`typing.Protocol`). |
| adapters | `src/adapters/` | реальные реализации портов (stdlib). |
| app | `src/app/` | стадии + раннер: композиция портов, никакого прямого I/O. |
| config / cli | `src/config/`, `src/cli/` | загрузка конфига, точка входа `argparse`. |

Всё внешнее подменяется фейками в тестах (`tests/conftest.py`), поэтому логика приёма
проверяется без диска и без реального `ds`.
