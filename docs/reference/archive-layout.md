# Раскладка источника: upload/, archive/, quarantine/

Источник: `src/app/ingest.py`.

Всё, что относится к источнику — его конфиг и весь бэкап когда-либо загруженного в него —
лежит в одной директории, `sources_dir/<source>/`:

```
sources/
├── crm/
│   ├── source.json                              ← конфиг источника (ds/docs/reference/config-format.md)
│   ├── upload/                                   ← сюда продьюсер кладёт новые файлы
│   │   └── crm_2026-08-25_09-00-01_000000.json   ← ещё не обработан
│   ├── archive/                                  ← успешно загруженные
│   │   ├── crm_2026-08-24_18-08-16.json
│   │   └── crm_2026-08-25_09-00-00.json
│   └── quarantine/                                ← ошибки
└── erp/
    ├── source.json
    ├── upload/
    ├── archive/
    │   └── erp_2026-08-24_18-09-00.json
    └── quarantine/
```

Источником считается только поддиректория `sources_dir`, в которой есть `source.json` —
то же самое, что уже требуют `ds upload`/`ds get`. Поддиректория без `source.json`
стадией `ingest` не трогается (не сканируется, `upload/` в ней не создаётся).

## `upload/` — что мониторит `ingest`

Создаётся автоматически на каждом тике, если его ещё нет (`ctx.fs.mkdir`), даже если он
пуст. Имя файла внутри — по-прежнему `<source>_YYYY-MM-DD_HH-MM-SS_<micros>.json`
([`file-naming.md`](file-naming.md)); префикс `<source>_` в имени должен совпадать с именем
папки — при расхождении файл не трогается, в отчёте `skipped-misfiled` (защита от
случайно не в ту папку положенного файла).

## Успешно обработанные → `archive/`

- имя файла — без микросекунд (`<source>_YYYY-MM-DD_HH-MM-SS.json`);
- перемещение происходит **после** записи в журнал (см.
  [`../explanation/exactly-once.md`](../explanation/exactly-once.md)).

## Ошибки → `quarantine/`

```
sources/crm/quarantine/
├── crm_2026-08-24_18-08-16_552252.json       ← исходное имя, с микросекундами
└── crm_2026-08-24_18-08-16_552252.json.err
```

Сюда файл уходит, если:

- `ds upload` вернул ненулевой код (в `.err` — его stderr/stdout; в т.ч. отказ строгой
  проверки — новый показатель или значение не по объявленному типу);
- метка времени в имени не парсится в дату.

В карантине имя **сохраняется как было** (с микросекундами) — чтобы файл можно было
разобрать и, при желании, вернуть в `upload/` после починки.

Файл, чьё имя вовсе не подходит под шаблон (`skipped-name`) или чей заявленный в имени
источник не совпадает с папкой (`skipped-misfiled`), в карантин **не** уходит — остаётся на
месте, в отчёте только строка лога (см. [`file-naming.md`](file-naming.md)).

## Журнал → `ledger_path`

Общий на все источники (не разбивается по `sources_dir/<source>/` — это отдельный,
глобально сквозной journal, а не бэкап). JSONL, по строке на успешно загруженный файл:

```json
{"key":"crm_..._552252.json:1a2b3c4d5e6f7a8b","file":"crm_..._552252.json","source":"crm","dt":1787602096,"loaded_at":1787602100.5,"stdout":"loaded 6 transaction(s)"}
```

`key` = `<имя файла>:<sha256(содержимого)[:16]>`. Битые строки при чтении пропускаются —
журнал остаётся рабочим.
