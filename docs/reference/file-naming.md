# Формат имён входных файлов

Источник: `src/domain/naming.py`, `src/domain/timestamps.py`.

## Шаблон

```
<source>_<YYYY-MM-DD>_<HH-MM-SS>_<micros>.json
```

Пример: `mashkinas_2026-08-24_18-08-16_552252.json`

| Часть | Правило |
|---|---|
| `<source>` | всё до **первого** `_`. Любые символы, кроме `_`. |
| дата/время | ровно `YYYY-MM-DD_HH-MM-SS` (нули значимы). |
| `<micros>` | 1–6 цифр. `datetime.strftime("%f")` даёт 6; более короткие тоже принимаются. |
| расширение | строго `.json`. |

Продьюсер формирует метку так:

```python
timestamp = datetime.now(timezone.utc).strftime("%Y-%m-%d_%H-%M-%S_%f")
```

## Как метка превращается в `--dt`

`ds` ожидает бизнес-время в unix-секундах. `ds-loader` парсит метку форматом
`%Y-%m-%d_%H-%M-%S_%f`, **отбрасывает микросекунды** и переводит в unix:

- `filename_tz = "utc"` (по умолчанию) → `calendar.timegm(...)` — не зависит от TZ машины;
- `filename_tz = "local"` → `datetime.timestamp()` — совпадает с локальным продьюсером на
  той же машине.

> Если продьюсер пишет **локальное** время (`datetime.now()` без `tzinfo`), а машины в
> разных поясах — выставь `filename_tz` явно. Рекомендуется договориться на UTC в продьюсере.

## Некорректные имена

- не подходит под шаблон → файл **не трогается**, в отчёте `skipped-name`;
- подходит, но дата невозможна (`2026-13-40_99-99-99`) → в `quarantine/<source>/` + `.err`.
